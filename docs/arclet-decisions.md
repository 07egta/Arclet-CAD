# Arclet の設計判断

決定日: 2026-11-01。利用者の最新の希望に従い、Melt3D への追加ではなく、独立した CAD アプリを作る。
公開名は開発名 **Arclet CAD**。実行ファイルは `arclet`、アプリ ID は `arclet-cad`、設定も独立させる。
既存の Melt3D の画面と起動経路を置き換えない。

## 1. アプリを分け、許諾されたコアを共有する

`apps/arclet` に独立した egui の画面を置き、`geom`、`sketch`、`kernel`、`doc`、`engine`、`ui-egui` の
Rust コアを利用する。別の幾何エンジンを一から重複して作るより、既存の文書・拘束・履歴・解析を使い、
曲線と曲面を編集する一連の操作に時間を使えるため。`apps/meltcad` を依存先にはしない。

言語は Rust を継続する。型、幾何の処理、文書、UI を native と wasm で共有でき、別言語の実行環境を必要としないため。
配布条件は既存コアと同じ MIT OR Apache-2.0 とし、[ライセンス](../LICENSE-MIT)と
[Apache-2.0](../LICENSE-APACHE)、[第三者の条件](../THIRD-PARTY-LICENSES.txt)、
[素材の出典](../ATTRIBUTION.md)を維持する。

Arclet 単体の Linux ビルドは X11 / XWayland を使い、eframe のネイティブ Wayland 機能は選ばない。
Plasma のプロトコル資料に別の配布条件がある依存を、新しいアプリへ含めないため。
Rust 部分のライセンス表記だけで、同梱資料すべての条件が同じとは判断しない。
配布用には実際に選ばれる依存関係と各 NOTICE・フォントの条件を確認する。Windows / macOS の方式は変えない。

Serpentine3D は公開文書のコマンドと挙動を比較する資料にとどめる。製品や copyleft の実装は参照しない。
Rhino / Plasticity の公開マニュアル、一般的な数学、独自の解析テストから仕様を決める。

## 2. 見える操作と軽い画面を先に作る

上部は `Model` / `Nodes` と、名前付きの主要ツールに絞る。`Curve`、`Surface`、`Solid`、`Transform`、
`Select`、`Analyze`、`View` の入口、常設のコマンド欄、`All tools` を用意する。
ショートカットは追加の近道で、操作を覚えなければ機能を発見できない構成にはしない。
選択対象、数値、プレビュー、確定・取消を同じ作業の中で確認できるようにする。
ビュー内の右クリックと Finish は、既存のツール終了・パネル確定の経路に接続する。
入力の再検証を省略せず、削除の明示確認には使わない。この操作は Arclet のみで有効にする。

色、元から許諾されたアイコン、UI 部品、カメラ操作は共有の実装を使う。
Arclet の初期ナビゲーションは中ボタンで回転、Shift と中ボタンで移動。
この初期値は Arclet の設定だけに適用し、既存アプリの初期値を変更しない。Settings で他の操作へ切り替えられる。
軽さは目標であり、GPU 別の性能を測る前に保証値は書かない。

公開資料から採った操作と根拠は [曲線・曲面の調査](arclet-surface-workflows.md) と
[Plasticity の操作調査](arclet-usability-research.md) に残す。レビューは使い勝手の意見として扱い、
精度、速度、現行バージョンの機能を証明する資料にはしない。

## 3. NURBS は編集と計測を分けて進める

優先する往復は **Spline → Rebuild → 偏差・連続性を確認 → 面を作る → Zebra 等で確認**。
曲線のコアには正の重みとノット列の検証、3 階までの微分、曲線の方向を持つ `CurveChain` を追加する。
Rebuild は両端を固定して次数・点数を変更し、元の曲線を残す。最初から周期曲線や端の接線拘束まで広げず、
既存文書へ保存できる CV Spline を出力する。重複輪郭が押し出しを妨げないよう、新しい曲線は作図用が初期値。

偏差は両方向の標本点から折れ線への推定距離として表示する。曲線端の G0–G3 は、位置、接線、曲率ベクトル、
弧長に対する曲率ベクトル変化を、明示した許容値で順に判定する。元の曲線を保持し、確定前に判断できるようにする。
一般曲面の継ぎ目検査は現在 G0–G2 の標本検査であり、曲線端の検査とは区別する。

既存の Match / Fair に実際の選択・設定パネルを付け、既存の Loft / Blend / Boundary と解析表示への入口を整える。
G3 を入力できる処理と、結果を独立に証明する処理は別に評価する。Class A 品質や xNURBS 互換は宣言しない。
Plasticity PolySplines のようなメッシュから曲面への変換は、通常の CurveChain とは別の後続課題。

## 4. 長い処理と保存を画面から分離する

native のノード評価は一つの中止可能なワーカーで処理する。変更後の結果には版番号を照合し、古い結果を採用しない。
CAD のプレビューと確定も既存のワーカー経路を使う。最大個数・最大サイズ・有限値の検査を行う。
ブラウザのノード評価は一フレームごとの制限を設ける。Print、新しい Rebuild・曲線端検査・Match・Fair は
Web Worker が整うまで使用を拒否し、画面を止める実装を成功扱いにしない。

CAD 文書とノードグラフは別ファイルとする。既存の CAD 文書形式を急に変更せず、グラフは検証付きの版管理 JSON に保存する。
既存の `melt3d.node-graph` 識別子は交換形式の互換性のため維持し、アプリ名には使わない。
ノードの結果は `Add to model` を押したときだけ現在の文書へ追加する。評価だけでモデルを置き換えない。
追加の準備中に文書が変わった場合は、その結果の追加を拒否する。

native は非同期のファイル選択と保存経路を使う。ブラウザはファイルをアップロードし、Save でコピーをダウンロードする。
保存元の上書きやブラウザ内の CAD 文書の永続保管は提供していないことを画面と README に示す。
グラフの設定内スナップショットは補助であり、明示的な JSON 保存の代わりにはしない。

保存先はホストが `Services.paths` で明示する。Arclet の native では専用のデータフォルダー配下に
復旧用コピー・クラッシュ記録の一覧・プラグイン一覧を分け、旧 SolidCraft のフォルダーを暗黙に選ばない。
共有 UI の復旧操作やスクリプトも同じ指定を使う。利用者が回復コマンドへ明示した `dir` は尊重する。
既存ホストは `paths: None` で従来の保存先を維持するため、別アプリの初期値を変更しない。
Arclet のブラウザ版はこれらの保存先を無効にし、CAD 文書の永続的な自動保存・復旧は後続課題とする。

## 5. 印刷と検証の線引き

ノードからスライサーへつなぐ経路と、上下スキン・層ごとの充填率は残す。
Bambu A1 / A1 mini の実機印刷、専用の開始・終了 G-code、AMS 用の `.gcode.3mf` は **未確認・未実装** の範囲を明記する。
通常の形状用 3MF の書き出しを印刷ジョブ作成と呼ばない。

コンパイル、幾何の自動テスト、画面の操作試験、GPU 性能、プリンターの実機確認はそれぞれ別に記録する。
コマンド登録数やメニューの存在を、その機能があらゆる入力で完成した証拠にしない。
リポジトリ全体のチェックに既存の失敗がある場合は、今回の変更の確認結果と分け、無関係な整形には触れない。

起動方法と現在の対応範囲は [Arclet README](../apps/arclet/README.md)、
ノードの形式・上限は [Node editor](node-editor.md)、スライサーは [Solid skins](slice-skins-density.md) に記載する。
